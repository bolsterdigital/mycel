# Assistance data contract

Assistance is off for each tenant until an administrator enables it and consents to the configured provider label. The hoster may disable the feature through `ai.assist`. Restricted items require a separate `allowRestricted` setting. A request reserves one monthly suggestion and creates a pending row; a worker calls the provider outside the tenant transaction. A provider error leaves a failed suggestion with an error class, never its response body.

| Task        | Sent to the provider                                                                                                                      | Never sent                                                      |
| ----------- | ----------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------- |
| Image alt   | One re-encoded WebP variant, at most 960 pixels wide, the image block's caption in the requested locale when present, and the locale code | Original upload, filename, credit, other blocks, title, authors |
| Translation | Chosen source values and the source and target locale codes                                                                               | Other locales or blocks, authors, forms, supporter data         |
| Lead        | The locale code and the plain text of one to three chosen rich-text blocks in that locale, including the words of a link                  | Title, other blocks and locales, link targets, footnotes, media |

No operator id, email address or tenant name is sent. A model result is a proposal. An editor may adjust or dismiss it; only acceptance creates a revision and no acceptance publishes content. The accepted row loses its output immediately. Pending rows older than ten minutes read as failed. The daily retention job deletes rows older than `ASSIST_RETENTION_DAYS` (default 30). A content-free monthly counter keeps the full calendar month's usage even when a 30-day-old suggestion is deleted on day 31. Tenant export includes the consent settings and excludes suggestions and usage counters. No supporter data belongs in this store.

## Translation proposals

`assist.translation.suggest` accepts a source locale, a target locale and selected document fields (`title`, `lead`, `seo.title`, `seo.description`) or block ids. A block id expands only to its localised fields. The worker sends one JSON text part containing the two locale codes and only those source values. Rich text uses the lossless core Markdown subset. No other locale, block, author, form, supporter, operator id, address or tenant name is included. Links, footnote identifiers, heading levels and list item counts must survive; a changed structure produces `invalid-output` without a ready proposal. Acceptance writes an unpublished revision with provenance and records a locale-wide review requirement in `machineTranslation[locale] = ["locales"]`. The reserved `locales` marker survives every ordinary revision write, including replacement block ids, splits, merges, rewritten text and deletion of all translated fields. Legacy nonempty field-path lists already block readiness and are upgraded on the next write. Empty or absent metadata creates no requirement. Client metadata cannot clear a stored requirement. While any locale awaits review, every other locale whose complete localized projection changes also requires review, even for an independent human edit. Removing or renaming a pending locale is refused. Changes to free text outside that projection (canonical URLs, tags, delivery list slugs, credits, quote names/URLs, action URLs and video ids) are refused until pending locales are approved; immutable item slugs are outside revision writes. Validated non-text controls remain editable. Only `content.translation.approve` by an operator with `content:publish` removes the requirement for that one locale; until then locale readiness refuses both publication and scheduling. Approval changes neither text nor existing publication or schedule pointers; a later translation acceptance requires review again. The task descriptor uses the suggestion row's `block_id` field; since migration 0065 the row also names its task (`alt`, `translate` or `lead`). The output row remains operational and follows the existing retention rule.

## Lead proposals

`assist.lead.suggest` takes an article, its base revision, one of its locales and one to three distinct `rich-text` block ids in document order. Each block must hold words in that locale, and their plain text together may not exceed 3,000 characters; a longer selection is refused, never cut. Before requesting, the editor sees exactly the chosen passages and the processor label; there is no free prompt. The worker sends one text part with the locale code and one text part per chosen block: paragraphs, headings and list items as plain lines, a link's visible words without its target, and no footnote marker or note. No title, other block or locale, author, media, form reference, tenant name, operator identity or supporter data is sent, and neither HTML nor ProseMirror JSON leaves the installation. Just before the call the worker checks the revision, the selection, the tenant setting, consent, entitlement and `allowRestricted` again; a changed or removed source block fails the task as `rejected`. The model returns `{ lead }`: one trimmed paragraph of 1 to 1,000 characters without line breaks or markup; anything else is `invalid-output`, without the model's text in an error, log or audit field. The schema checks the form, not the facts: the editor judges whether the lead is true to the text. The row stores the task and the source block ids (migration 0065), never the passages. Only an operator with `content:write` accepts, on the newest revision; an edited value passes the article's own lead schema. Acceptance writes one unpublished revision that changes only `lead[locale]`, with provenance (`suggestionId`, `task: 'lead'`, provider, model, edited) and no source text; publication and schedule pointers stay as they were.

## Constants

| Constant                 | Value                                      | Where                                     | Why                                                                                |
| ------------------------ | ------------------------------------------ | ----------------------------------------- | ---------------------------------------------------------------------------------- |
| quota month              | calendar month in UTC                      | `packages/core/src/assist/service.ts`     | `ai.monthly_max` counts requests since the first of the month, 00:00 UTC           |
| `PENDING_TIMEOUT_MS`     | 10 min                                     | `packages/core/src/assist/model.ts`       | a pending proposal older than this has timed out; also bounds the pending throttle |
| `OPERATOR_WINDOW_MS`     | 1 h                                        | `packages/core/src/assist/service.ts`     | the window of the per-operator throttle `ai.operator_hourly_max`                   |
| `ai.monthly_max`         | 2,000                                      | `packages/core/src/entitlements/model.ts` | default monthly suggestion quota per tenant                                        |
| `ai.pending_max`         | 3                                          | `packages/core/src/entitlements/model.ts` | default number of pending suggestions per tenant                                   |
| `ai.operator_hourly_max` | 30                                         | `packages/core/src/entitlements/model.ts` | default requests per operator per hour                                             |
| retry delay              | 30 s, one retry                            | `packages/core/src/assist/worker.ts`      | a timeout or unavailable provider is retried once before the suggestion fails      |
| alt image width          | at most 960 px                             | `packages/core/src/assist/worker.ts`      | the widest WebP variant up to this width is sent, never the original               |
| `maxTokens`              | 200 (alt), 3,000 (translation), 600 (lead) | `packages/core/src/assist/worker.ts`      | bounds the provider answer per task                                                |
| `LEAD_SOURCE_MAX`        | 3,000 characters                           | `packages/core/src/assist/lead.ts`        | the most chosen text one lead request may send; longer is refused, not cut         |
| `ASSIST_TIMEOUT_MS`      | 30 s (1 s to 120 s)                        | `packages/api/src/runtime/config.ts`      | the provider call is aborted after this                                            |
| `ASSIST_RETENTION_DAYS`  | 30 (1 to 365)                              | `packages/api/src/runtime/config.ts`      | suggestions older than this are deleted by the daily retention job                 |
