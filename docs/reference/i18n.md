# Internationalisation

How Mycel keeps copy, content and locales apart. [ADR 007](../adr/007-i18n-from-day-one.md) names three concerns with a mechanism each: UI and domain copy live in typed message catalogs, content is stored as `{ [locale]: value }` on one document, and formatting uses `Intl`. Readiness per locale comes from [ADR 018](../adr/018-precise-editorial-operations.md) rule 9. Code: `packages/core/src/i18n/` (domain catalogs, the `Locale` schema, `localized()`) and `apps/web/src/i18n/` (UI catalogs). How content documents use it is in [content-model.md](content-model.md); localised form labels are in [forms.md](forms.md).

## Locale codes

`Locale` (`packages/core/src/i18n/locale.ts`) accepts a BCP 47 subset: a two- or three-letter lower-case language, optionally a hyphen and a two-letter upper-case region (`nl`, `en`, `de`, `pt-BR`). The public route's `locale` param matcher (`apps/web/src/params.ts`) repeats the same pattern, because matchers are bundled for the browser and must not import core; `params.test.ts` keeps the two equal.

## Localised fields

A localisable field is built with `localized(schema)`: a record from `Locale` to the value, refused when empty (`i18n.localized.empty`). There is no separate document per language. Helpers in the same file:

| Helper            | Does                                                                                             |
| ----------------- | ------------------------------------------------------------------------------------------------ |
| `pick`            | the value for a locale, else the document's default locale                                       |
| `coversLocales`   | whether a value has an entry for every given locale                                              |
| `negotiateLocale` | the best of a list for an `Accept-Language` header: exact match, then primary tag, honouring `q` |

A content document declares `defaultLocale` and `locales` (1 to 10, no duplicates, the default among them; the database repeats the check on `content_items`). Every save refuses a value for a locale the document does not have (`i18n.locale-not-in-document`) and a default outside the list (`i18n.default-not-in-locales`). Drafts may miss translations.

## Readiness per locale

Each locale of an item is published on its own (`content_item_locales`, one pointer and one scheduled pin per locale). `readinessIssues(doc, locale)` in `packages/core/src/content/model.ts` is what stops one locale from being published: the locale must be one of the document's, every required visible field must have a value in that locale with no fallback (`content.publish.missing-translation`), and a field listed in `machineTranslation` for that locale is unreviewed and blocks publishing. Other locales are unaffected.

## Tenant locales and URLs

A tenant has `locales` and `default_locale` (migration 0001; default `['nl']` and `nl`; `DEFAULT_TENANT_LOCALES` in `packages/core/src/tenants/platform.ts`). `planTenant` takes the first locale as default when none is given and refuses a default outside the list. `mycel_app` reads both through the `tenant_directory` view.

The default locale has no prefix; every other locale of the site is under `/<locale>/` (`apps/web/src/lib/server/content-route.ts`). `localeOf` returns the default for no prefix, the prefix when it is one of the site's other locales, and `null` (a 404) for the default with a prefix or a locale the site lacks. The prefix is never negotiated or redirected: the path is the locale, so a response depends on its URL alone. `contentPath` in `packages/core/src/content/public.ts` builds the same shape. A public page carries one `hreflang` link per published locale plus `x-default` (the tenant default when the item has it, else its first locale; `apps/web/src/lib/server/public-page.ts`).

## Admin locale versus content locale

The operator admin's own language is negotiated from `Accept-Language` among `ADMIN_LOCALES` (`nl`, `en`) with `en` as fallback (`apps/web/src/lib/server/admin/admin.ts`); it has nothing to do with the tenant's locales. The content locale is a property of the document and of the public URL. `hooks.server.ts` writes whichever the route chose into `<html lang>`. The confirmation page uses the submission's locale when the site has it, else negotiates among the site's locales (`apps/web/src/lib/server/confirm.ts`); the confirmation mail is rendered in the locale of the submission.

## Catalogs

| Catalog | Where                                   | Holds                                                    | Lookup               |
| ------- | --------------------------------------- | -------------------------------------------------------- | -------------------- |
| domain  | `packages/core/src/i18n/en.ts`, `nl.ts` | validation messages, refusal reasons, e-mail boilerplate | `t`, `translate`     |
| UI      | `apps/web/src/i18n/en.ts`, `nl.ts`      | public chrome and the operator admin                     | `ui(locale)`, `fill` |

English is complete in both and defines the key type (`MessageKey`, `UiKey`); other catalogs are `Partial` and fall back to English key by key, first by exact locale, then by primary tag. `{name}` placeholders are interpolated. Use cases return i18n keys, not text (field errors of `form.submit`, Zod issue messages); fronts translate them with `translate`, which passes an unknown key through unchanged.

**Adding a key.** Add it to the English catalog (the type follows), then to `nl.ts`. For the domain catalog `packages/core/src/probe.test.ts` fails when `nl` misses a key of `en`. The UI catalog has no such test: a missing Dutch key silently falls back to English.

## Constants

| Constant                 | Value                            | Where                                    | Why                                                        |
| ------------------------ | -------------------------------- | ---------------------------------------- | ---------------------------------------------------------- |
| `DEFAULT_LOCALE`         | `en`                             | `packages/core/src/i18n/index.ts`        | platform default and the complete catalog (ADR 007 rule 4) |
| `DEFAULT_TENANT_LOCALES` | `['nl']`                         | `packages/core/src/tenants/platform.ts`  | a new tenant without locales is Dutch                      |
| `ADMIN_LOCALES`          | `nl`, `en`                       | `apps/web/src/lib/server/admin/admin.ts` | the admin ships in both (ADR 007 rule 4)                   |
| `Locale` pattern         | `^[a-z]{2,3}(-[A-Z]{2})?$`       | `packages/core/src/i18n/locale.ts`       | the BCP 47 subset accepted everywhere                      |
| `LocaleList`             | 1 to 10                          | `packages/core/src/content/model.ts`     | locales per content document                               |
| platform API locale      | 2 to 10 characters, at least one | `packages/api/src/platform.ts`           | input bound for `POST /platform/tenants`                   |
