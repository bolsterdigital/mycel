# Content model

How pages and articles are stored, revised, published per locale and scheduled (PR #14). The decisions are in [ADR 012](../adr/012-content-types-and-publishing.md), [ADR 018](../adr/018-precise-editorial-operations.md) and [ADR 020](../adr/020-editing-surface-and-block-operations.md); this page records the choices made while building them, so the block, rendering and feed work build on them instead of choosing again. Code: `packages/core/src/content/`, migration `0011_content_items_and_revisions.sql`, repositories in `packages/db/src/content.ts`.

## Item, revisions, locales

| Table                  | One row per             | Holds                                                                                                                                                            |
| ---------------------- | ----------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `content_items`        | page or article         | id (UUIDv7), type (`page`, `article`, never changes), slug, latest revision id, title/locales of the latest revision for lists, created and updated time         |
| `content_revisions`    | save                    | the whole validated document (`ContentDocument`), the acting principal, the time. Never updated: `mycel_app` may only insert and select                          |
| `content_item_locales` | item and locale         | the live pointer (`published_revision_id`, `published_at`, `first_published_at`) and the scheduled pin (`scheduled_revision_id`, `scheduled_for`, `schedule_id`) |
| `authors`, `sections`  | author profile, section | tenant entities with their own slug space; an author's `email` is internal                                                                                       |
| `patterns`             | saved block tree        | localised name and description, intended type, blocks; applying one copies the blocks with new ids                                                               |

Every pointer is a composite foreign key on `(tenant_id, item_id, revision_id)`, so a locale can only point at a revision of its own item in its own tenant. All six tables have forced RLS and the `tenant_isolation` policy (ADR 002).

**Status is derived, per locale** (ADR 018 rule 9): `published` while a live pointer exists, `scheduled` while only a pin exists, `unpublished` once it has been live, `draft` before that. The column is generated in SQL and computed the same way by `statusOf` in `lifecycle.ts`. "Published with unpublished changes" is `hasUnpublishedChanges`: the latest revision is not the live one. There is no global status that switches all locales at once.

## Documents and blocks

A document is `{ type, title, defaultLocale, locales, blocks, lead?, heroImageId?, heroAlt?, featuredImageId?, featured?, seo, access }`; an article adds ordered `authorIds`, `sectionId`, `tags`, `corrections` and `delivery`. Every localisable field is a `{ [locale]: value }` map on the same document (ADR 007), and a value for a locale the document does not list is refused. `lead` is the introduction under the title, on pages and articles alike (#86). Three images name a media id and follow the image-block rules below: `heroImageId` is the image on the item's own page, `featuredImageId` (ADR 012 rule 1, amended 2026-10-29) the image where the item is featured elsewhere, `seo.imageId` the share image. `featured.title` and `featured.description` are the title and description where the item is featured; they never replace the title in `<title>` or the SEO title. Alt text belongs to a use. The featured and share image carry none. The hero is decorative unless `heroAlt` (#99) describes it: a localised map, only next to a `heroImageId`, never empty or blank, and once present required in every published locale like any visible field; the public projection gives the alt of its locale or null. Either way the hero shows the asset's caption and credit under the title and lead. Title, lead and hero form the document header (ADR 025): metadata above the blocks, not a block.

An empty field inherits along one chain, computed by the pure functions in `content/effective.ts` and returned as `effective` by `content.item.get` (per locale) and `content.published.get` (the asked locale), each value with the link it came from (`source`):

| Value           | Chain                                                                                             |
| --------------- | ------------------------------------------------------------------------------------------------- |
| hero image      | `heroImageId`, else none                                                                          |
| featured image  | `featuredImageId` → hero → the site's default image                                               |
| share image     | `seo.imageId` → featured → hero → the site's default image                                        |
| featured title  | `featured.title` → `title`                                                                        |
| summary         | `featured.description` → first paragraph of `lead` → first paragraph of the first rich-text block |
| SEO description | `seo.description` → summary                                                                       |

A derived text has its whitespace folded and is cut at a word to at most 300 characters; an own value is returned as written. The site's default image is an argument of the chain, stored as the site setting `images.defaultImageId` (`site.image.get/update`, see `theme.md`). Nothing derived is stored on the revision.

- **Block ids** (ADR 020 rule 1): a string of `A-Z a-z 0-9 _ -`, at most 64 characters, unique in the whole document. A caller may omit the id of a new block and the core assigns a UUIDv7; ids that are sent are kept. At most 200 blocks per document. Two `rich-text` blocks are never adjacent in one block list.
- **Block set**: the four types of #8a (`heading`, `signup-form`, `rich-text`, `paywall`) plus the cards of #8b2 (`image`, `hero`, `cta`, `callout`, `faq`, `quote`, `video-embed`, `form`); see [Blocks](#blocks) below.
- **Rich text** (ADR 020 rule 2): ProseMirror JSON with `doc`, `paragraph`, `text`, `heading` (relative level 1 to 3; consecutive headings never skip a level), `bullet_list`, `ordered_list` (optional `start`), `list_item` (starts with a paragraph) and `hard_break`. Marks: `bold`, `italic`, `code`, `link` and `footnote_reference` (the note's text in its attributes). Lists nest at most three levels deep, at most 5000 nodes and 100 000 characters per locale. Every node and mark is a strict object: unknown nodes, marks or attributes are refused.
- **Links** carry exactly one target: `href` (http or https without credentials, `mailto:`, or a site path starting with a single `/`) or `itemId`, a content item of the same tenant. Internal links to content use `itemId`, so a later slug change (#9) cannot break them.

## Readiness and references

Drafts may miss translations. Publishing or scheduling a locale requires (`readinessIssues`):

- the locale is one of the document's;
- the title and every required visible field have a value in that locale (block text, rich text, card titles, bodies, action labels, FAQ questions and answers, quote text, image alt text, an article's lead once it has one in any locale, corrections, the e-mail subject when `delivery.email` is set), with no fallback. An optional visible field (a caption, a hero body, a quote's role) counts once it is filled in any locale, so half a translation never falls back;
- an article has at least one author;
- a restricted article with the default `lead` teaser has a lead;
- `access.level: tier` fails closed until #19 can verify tier ids.

SEO overrides are optional per locale: absent means derived (title, lead), present must not be empty.

References are checked on every save (create, update, every block operation, pattern create and update) and again at publication, scheduling and the scheduled job: forms, linked items, authors, the section and media must exist in the tenant. Media must also not be deleted and must be an image (`content.reference.media-not-image` with `params.id` for a PDF); restricted media may be referenced, which grants no reader access. Lookups run under RLS, so another tenant's id is simply unknown (`content.reference.media-unknown`, the same as an id that never existed); the error names the path, never whether the id exists elsewhere.

## Access and teaser

`access: { level: public | members | tier, tierIds?, teaser }` on pages and articles alike (ADR 016 rule 3, ADR 018 rule 6). `teaser` is `lead` (default), `marker` (exactly one `paywall` block at the top level of the tree) or `{ blocks: n }` (an integer from 0 up to the number of top-level blocks). A `paywall` block without the marker teaser is refused. Restricted content is never served by the public projection (`content.published.get`), in any representation: HTML, the JSON read route and MCP answer it with the same 404 as a missing item. #19 brings the reader session and the teaser projection.

## URLs, slugs and tags

- One slug per item, not localised in v1: lowercase ASCII, digits and hyphens, starting with a letter or digit, at most 63 characters. Unique per tenant and type (`unique (tenant_id, type, slug)`); authors and sections have their own slug spaces.
- Paths (delivered in #8c2): pages at `/<slug>`, the page with slug `index` at `/`, articles at `/articles/<slug>`, a form's thank-you page at the item's path plus `/thanks`. A non-default locale of the site is a prefix (`/en/...`); the default locale has none, and `/nl/...` on an nl site is a 404, not a redirect (ADR 007 rule 3). The path is the locale: content paths never negotiate from `Accept-Language`, and an unpublished locale is a 404, never a fallback. `/index`, `/articles` and the other list roots are 404 until #9 brings author and section archives at `/authors/<slug>` and `/sections/<slug>` and tags at `/tags/<tag>`. `contentPath` (`content/public.ts`) builds a site-root path; absolute URLs are that path through `siteUrl` only. The grammar is `parseContentPath` in `apps/web/src/lib/server/content-route.ts`.
- **Head**: every published page or article has `<html lang>` from the path, a `<link rel="canonical">` with its absolute URL, one `<link rel="alternate" hreflang>` per published locale plus `x-default` (the default locale when it is published, else the first published one), a `<title>`, a `<meta name="description">` (`seo.description`, else the lead, else the first paragraph) and the Open Graph set: `og:type` (`article` or `website`), `og:title` (`seo.title`, else the title), `og:url` (the canonical URL), `og:description`, and with a share image `og:image` with its type, width and height plus `twitter:card` `summary_large_image` (else `summary`). The share image is the widest webp variant up to 1280 px through the site's own `/media/<id>/<file>` route, and only for a public, ready image; a JPEG made for sharing is the og-image generator's (`og:<...>` usages). `noindex` and the rest of the SEO set are #9.
- **Caching**: a published item's HTML is `Cache-Control: public, max-age=60, stale-while-revalidate=600` with a strong `ETag` `"<revision>:<locale>:<theme hash>:<digest>"`, where the digest covers what the page shows beyond the revision (resolved links and images, the head, the site's entitlements); a matching `If-None-Match` is a `304`. An item that renders a form is the exception: `no-store` without an ETag, because its HTML carries a signed timing token per visitor, and a revalidated copy would keep an old token alive past its 24 hours and stop measuring how long this visitor took to fill in the form (#30A). The current first-party public content route reads or sets no cookie, so it needs no `Vary`; [ADR 022](../adr/022-managed-extensions-and-site-integrations.md) requires separate consent and cache review for future site integrations and makes no blanket no-cookies claim. A form post's answer and a thank-you page are `no-store`, and so is every 404 on the public site, so an item that is published later is never hidden behind a cached miss. ADR 018 rule 8's rules for restricted content (`private, no-store`, `Vary: Cookie`, a separate teaser key) come with #19.
- **JSON read route** (ADR 012 rule 7): `GET /v1/sites/{tenant}/content/{type}/{slug}?locale=` on the API, without an API key. The tenant is its slug in the path; the route runs `content.published.get` as that site's anonymous visitor and returns the `PublishedItem` (with `featuredImageId` and `seo: { title, description, imageId }` in the chosen locale, `imageId` already falling back to the featured image) with the same cache rules (its ETag is revision, locale and a digest of the body). Unknown tenant, unknown item, unpublished locale and restricted item are one `no-store` 404 in Problem Details. Code: `packages/api/src/content-read.ts`; listed in `/openapi.json`. Lists (section, author, tag, feed) are #9.
- **Reserved page slugs**: `admin`, `api`, `internal`, `v1`, `confirm`, `reader`, `articles`, `authors`, `sections`, `tags`, `assets`, `_app`, `healthz`, `thanks`, `robots.txt`, `favicon.ico`, and every string that parses as a locale (two or three lowercase letters, optionally `-XX`), so adding a locale later can never shadow a page. The list is `RESERVED_PAGE_SLUGS` in `model.ts` and is checked when a page is created.
- A slug is chosen at create (or derived from the title) and does not change on update. `content.slug.update` changes it only while the item has never been published in any locale (no `first_published_at`): nobody can have linked to it yet, so no redirect is needed. A taken slug is a `conflict` with the issue `content.slug.taken`; the write decides (`ContentRepository.setSlug` returns false on the unique key), so two renames racing to one free slug cannot both win. Renames of published items, with redirects, are #9.
- **Tags** stay strings (ADR 012 rule 3). Their identity is the canonical form: Unicode NFC, trimmed, lowercase, runs of whitespace as one space; duplicates are dropped in input order. A canonical tag is letters and digits in words joined by single spaces or hyphens, at most 50 characters, at most 20 tags per article. No tag entity, id or rename in v1; stable term ids would need a successor to ADR 012 rule 3.

## Use cases

| Use case                                                              | Capability        | Notes                                                                                               |
| --------------------------------------------------------------------- | ----------------- | --------------------------------------------------------------------------------------------------- |
| `content.item.create`, `content.item.update`                          | `content:write`   | Update needs `baseRevisionId`; a stale base is a typed `conflict` with nothing written              |
| `content.slug.update`                                                 | `content:write`   | Only for an item never published in any locale; leaves revisions and publication untouched          |
| `content.item.get`, `list`, `revisions`, `diff`                       | `content:read`    | Editorial; lists are keyset pages, newest first; `diff` lists changed paths, blocks matched by id   |
| `content.item.publish`, `unpublish`, `schedule`, `unschedule`         | `content:publish` | One locale each; `effect: publish`. A manual publish or unpublish cancels that locale's plan        |
| `content.block.insert`, `move`, `remove`, `set_props`, `split_insert` | `content:write`   | One block by id; each needs `baseRevisionId` and makes one revision (see below)                     |
| `content.item.find`                                                   | `content:read`    | By block type and/or reference, latest or `live`; keyset pages, newest first                        |
| `content.author.*`, `content.section.*`, `content.pattern.*`          | write / read      | create, update, get, list                                                                           |
| `content.published.get`                                               | `content:read`    | The public projection: one published locale of a public page or article (`type`, `slug`, `locale?`) |

Every editorial use case is `authenticatedOnly`: an anonymous principal is refused whatever capabilities it holds, so a public visitor's `content:read` opens nothing but `content.published.get`. The registry rules require the flag for every `content.item.*`, `content.slug.*`, `content.author.*`, `content.section.*` and `content.pattern.*` use case.

Every write takes the item lock (`select ... for update` on the item row) first. Two saves on one base therefore end in one new revision and one `conflict`, and a publication change racing a save or a scheduled job serialises in lock order.

## Block operations and references

Five commands edit one block without sending the whole document (ADR 020 rule 6). Each takes `itemId` and `baseRevisionId`, runs the same path as `content.item.update` (item lock, base check, full document validation, reference checks, block switches, one attributed revision) and returns `{ item, revision, created, retired, merged }`:

| Use case                     | Input besides item and base                                   | Effect                                                                                                                           |
| ---------------------------- | ------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `content.block.insert`       | `block`, `place`                                              | A new block; a supplied id must be free, otherwise the insert is refused; an omitted id is generated                             |
| `content.block.move`         | `blockId`, `place`                                            | Same id at the new place, then normalise                                                                                         |
| `content.block.remove`       | `blockId`                                                     | The id is retired, then normalise                                                                                                |
| `content.block.update`       | `blockId`, `props`                                            | The complete props of that block's type; id and type stay. A locale left out of a localised field is removed from it             |
| `content.block.split_insert` | `blockId` (a `rich-text`), `at: { [locale]: index }`, `block` | Splits every locale of the text before `content[index]` and puts `block` between; the first part keeps the id, the second is new |

`place` is `{ before: id }`, `{ after: id }` or `{ at: 'start' | 'end' }`. Ids, never array indexes. An unknown `blockId` or anchor is `invalid_input` on that field (`content.block.unknown`, the id in `params.id`), never `not_found`: the item exists, the request does not fit it. A stale base is `conflict` with nothing written.

- **Normalisation** (ADR 020 rule 4): after a move or remove, adjacent `rich-text` blocks merge into the first one; per locale the ProseMirror `content` arrays are concatenated, so marks, attributes and headings stay. Two blocks without the same set of locales do not merge: the operation fails with `content.blocks.merge-ambiguous` (the block in `params.id`) instead of losing or inventing a translation. `merged` lists `{ from, into }`, `retired` the removed and merged-away ids. Insert and `set_props` never normalise; an insert next to a `rich-text` is refused as `content.blocks.adjacent-rich-text`, as an update is.
- **Split-and-insert**: `at` names every locale the block has (`content.split.locale-missing`, `content.split.locale-unknown`), and both halves keep at least one node (`content.split.empty-part`). A `rich-text` block as the inserted block is refused, because the result would be adjacent text.
- **Block switches**: every block type in a saved document or pattern must be on in the site's entitlements (`blocks.<type>`); a switched-off type is `limit_exceeded` with `entitlements.feature-off` on create, update, every block operation and pattern create/update.

`content_block_refs (tenant_id, item_id, revision_id, block_id, type, ref_id)` (migration 0017) records every structured reference of every revision: `form` (signup blocks), `item` (link marks with `itemId`, anywhere in a rich-text tree), `media` (`image` blocks and a hero's image) per block, and `author`, `section` and the document's own images (featured and share image, `media`) with a null `block_id`. `content.item.find` by a media id therefore also finds an item whose only use is its featured or share image, with no block ids. The content repository writes the rows from `documentReferences` whenever it inserts a revision, so no caller can forget them; like revisions they are immutable for `mycel_app`. In the same transaction the save records the revision's media usages (see [Media references](#media-references-and-the-media-lock)). Migration 0017 backfilled every existing revision per tenant; `packages/db/src/content-refs-migration.test.ts` replays that block.

`content.item.find({ blockType?, ref?: { type, id }, live?, type?, after?, limit? })` needs at least one of `blockType` and `ref` and returns `{ items, matches: [{ itemId, blockIds }], next }`. Without `live` it searches each item's latest revision; with `live: true` only revisions that a locale publishes (`published_revision_id`), never drafts or history. When both filters are set, a revision must satisfy both. `blockIds` are the union of matching blocks (of the type, or carrying the reference) in those qualifying revisions only; a document-level reference matches no block. The block-type filter is a containment query served by a GIN `jsonb_path_ops` index on `content_revisions.document`. `ContentRepository.liveReferences({ type, id })` counts the items whose published revision in any locale uses a reference: the hook for refusing to delete something live (ADR 004 rule 6). Both run under RLS, so another tenant's id finds nothing.

## Blocks

Every currently implemented type is one entry in `packages/core/src/content/block-types.ts`: its props schema and version, its enumerated props (`variants`), where its localised fields sit, which tenant data it references, and examples for every variant in Dutch and English. Schema, readiness, projection and reference extraction in `blocks.ts` are derived from those entries, so a new type touches one file; `find`, the API, MCP and the JSON Schema follow from the registry. Every props object is strict: an unknown prop, variant or version is refused. This stored block model permits enumerated layout values only, never a free class, style or CSS value. [ADR 022](../adr/022-managed-extensions-and-site-integrations.md) accepts a future reviewed extension contract for bounded parts, slots and style values without changing this current schema by implication.

| Type                                             | Props (besides `id`, `type`, `version: 1`)                                                                                                                                                                                        | Defaults                         |
| ------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------- |
| `heading`, `rich-text`, `signup-form`, `paywall` | Unchanged version 1 of #8a; no `variant`. `signup-form` stays a supported legacy type with its own entitlement                                                                                                                    |                                  |
| `image`                                          | `mediaId`, `decorative`, `alt` (localised, or null when decorative), `caption?` (localised, may be empty to hide the asset's), `credit?` (the media credit shape), `layout: content \| wide \| full \| float-left \| float-right` | `layout: content`                |
| `hero`                                           | `variant: minimal \| cover \| split`, `title`, `body?`, `image?` (image props, `layout: content` only), `actions` (0 to 2), `width`, `align`; cover and split require the image                                                   | `minimal`, `[]`, `full`, `start` |
| `cta`                                            | `variant: band \| card`, `title`, `body?`, `actions` (1 or 2), `width`, `align`                                                                                                                                                   | `band`, `content`, `start`       |
| `callout`                                        | `variant: info \| note \| warning`, `title?`, `body` (localised rich text)                                                                                                                                                        | `info`                           |
| `faq`                                            | v2: `variant: list \| accordion`, `title?`, `entries` (1 to 30 of `{ question, answer }`, the answer localised rich text), `width: content \| wide \| full`; entries are props, not blocks                                        | `list`, `content`                |
| `quote`                                          | `text`, `attribution: { name, role?, source?, url? }` (`name` a proper name, the same in every locale; `url` http or https), `variant: blockquote \| pullquote`, `width`                                                          | `blockquote`, `content`          |
| `video-embed`                                    | `provider: youtube \| vimeo`, `videoId` (YouTube 11 characters `A-Z a-z 0-9 _ -`, Vimeo 1 to 20 digits), `title`, `caption?`, `width`; never iframe HTML, an arbitrary URL or autoplay                                            | `content`                        |
| `form`                                           | `formId`, `variant: default \| card`, `width`; a reference to the form definition, no copied fields or consent texts                                                                                                              | `default`, `content`             |

`width` is `content | wide | full`, `align` is `start | center | end`. Text bounds: titles and other short text 1 to 200 characters, bodies and quotes 1 to 5000, captions 0 to 2000, labels 1 to 100. Optional text is absent until it is filled. An action is `{ label, target }` with `target` either `{ kind: 'item', itemId }` (resolved by the renderer after publication and access checks, never a stored slug) or `{ kind: 'url', url }` under the rich-text link rules (http or https without credentials, `mailto:`, or a site path). No card has child blocks: the id operations keep one flat list, and containers, named slots and composed blocks are #11.

FAQ v1 had no width field. Reads validate the exact old FAQ shape, then add `width: content` and version 2 in memory before validating the current document. Invalid old props, extra keys and future versions fail. Historical JSON revisions, published pointers and scheduled pins remain unchanged; a subsequent save creates a new version 2 revision.

**Projection** reduces every localised field, nested ones included (a hero's image alt and action labels, FAQ answers, a quote's role), to the requested locale; it is driven by the same field list as readiness, and the block conformance test proves it with a sentinel in the other locale. Stored revisions of #8a parse byte for byte: no type was renamed, no version raised and no default added to an original type. A later change to a stored schema needs a per-type forward conversion (ADR 004 rule 5), never defaults written back into old revisions.

**Rendering (#8c1).** Every type renders through `apps/web/src/lib/blocks/`: one server-side resolver (`resolve.ts`) turns the published projection of one locale into a plain render model, and one Svelte component per type plus `markdown.ts` render that model to HTML and Markdown; no component reads the database. Heading levels come from context, never from stored data: the document title is the only `h1`, the title of a top-level `heading`, `hero`, `cta`, `callout` or `faq` is `h2`, FAQ questions are `h3` (or `h2` when the FAQ has no title), and rich-text headings of relative level 1 to 3 sit one to three levels below the heading they are under; a depth above `h6` is refused, not clamped. A reference fails closed: a restricted, deleted or failed image renders nothing at all (no figure, path or alt; a cover or split hero without its image renders as minimal), an action whose item is not public and published in that locale is dropped, and a rich-text link to such an item becomes plain text. A video is a plain link to the provider. The conformance suite (`blocks.conformance.test.ts`, HTML snapshots per example and locale in `__snapshots__/`) and `apps/web/e2e/public-site.spec.ts` (two composed pages, axe, no JavaScript; the UI gate in `ui-gate.spec.ts`) import the examples above.

**Default patterns** (ADR 012 rule 8): `longReadPattern(locales)` and `photoStoryPattern(photos, locales)` in `patterns.ts` return a `PatternInput` with starter copy from the domain catalogs. A photo story requires real media ids of the tenant with alt text or `decorative`; without a photo it throws. Neither ships a global asset. The tenant check runs when the pattern is saved and again when it is applied; the choice interface is #11.

## Media references and the media lock

Every save records the media usages of its block tree in the same transaction: one row per distinct `(mediaId, blockId)` under `item:<itemId>:rev:<revisionId>`, plus `doc:hero`, `doc:featured` and `doc:seo` for the document's hero, featured and share image (the colon keeps those slots apart from every block id); a pattern under `pattern:<patternId>` with its own block ids. The repository silently skips an unknown or deleted id, so the save compares the count it recorded with what it asked for and throws `content.reference.media-unrecorded` on a shortfall, rolling back the revision, its `content_block_refs` and the usages together.

Retention is conservative: a new revision, an unpublish or a move does not remove the usages of older revisions, so `media.delete` refuses while any revision or pattern still uses the image and an old revision stays restorable. A pattern update replaces only that pattern's usages; applying a pattern copies its blocks with new ids and its own revision usages, so a later pattern change does not touch the item.

Saves and deletes serialise on the tenant's media lock (`pg_advisory_xact_lock`, the lock uploads take). A reference check that finds media takes it before reading; a pattern write takes it before reading the pattern; `media.delete` takes it before it reads the asset and its usage count. With an item the order is always item lock, then media lock. Either the save commits first and the delete sees its usage (`conflict`, `media.in-use`), or the delete commits first and the save finds the image gone (`invalid_input`) with nothing written. The memory port models the same exclusion. The featured and share image are checked like an image block (present, not deleted, an image, this tenant's), at their own paths (`featuredImageId`, `seo.imageId`), at every save and again at publish. Author images are not checked yet (#8c/#11).

## Scheduled publishing

`content.item.schedule({ itemId, revisionId, locale, at })` accepts a future time with an offset, checks readiness and references, writes the pin with a new `scheduleId` and plans a `content.publish` job in the same transaction. The job key is `content.publish:<itemId>:<locale>:<scheduleId>`: a reschedule or a second locale never collides with an open job of an older plan, and `mycel_app` needs no right to cancel jobs.

The handler (`publishScheduled`) locks the item and compares the job with the current pin. A cancelled, replaced or already executed plan is a successful no-op; an early run returns `{ next: scheduledFor }`; a suspended site returns `{ next: +1 day }` with the pin kept (ADR 015 rule 7, `requireActive`). Otherwise it checks readiness and references again and puts exactly the pinned revision live, clearing the pin in the same transaction. A failed check throws, so the worker's retry and exhaustion route applies and what is live stays live.

## Migration of the probe's pages

Migration 0011 converts every row of `pages` in SQL, once, inside the migration's transaction: same id, slug and times, a first revision (actor `system`, job `migration:0011`), block ids `md5(<page id>:<position>)` as a UUID (the same input always converts to the same ids), and a publication only for the locales in which the title and every heading have a value. Each row is validated against the shape the core accepts (block types, versions, props, locales, form references in the same tenant); a row that does not fit stops the migration with its page id and reason, and nothing is kept. The tenant context is set per tenant, so the conversion runs as a non-superuser owner under forced RLS. `pages` is dropped at the end. `packages/db/src/content-migration.test.ts` replays the conversion block of the migration file.
